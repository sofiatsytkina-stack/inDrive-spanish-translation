# Handoff: локализация Figma-макета inDrive Delivery на испанский (Colombia → Peru → Ecuador)

Этот пакет — всё, что нужно человеку **с платным доступом к Figma MCP** (у меня Starter-план,
20 вызовов инструмента в месяц, лимит выбран — см. ниже), чтобы продолжить и закончить работу без
необходимости заново всё это выяснять.

## Что нужно сделать (в этом порядке)

1. **Закончить Colombia** — перевести весь интерфейс на испанский и заменить плейсхолдерные данные
   (имена, адреса, цены/валюту, номера телефонов, флаг страны, гос. номера, фото курьеров) на
   колумбийские, на странице **Colombia** файла
   https://www.figma.com/design/2GDDIA8sTmlAARXtukZ6eB/Delivery-Product-Flow-Espanol — **не трогая**
   страницу **English**.
2. **Проверить** результат (скриншоты + сверка, что English не изменилась).
3. **Повторить для Peru**, затем **Ecuador** — по той же методологии, с той же таблицей
   (`localization-table.csv`), просто добавив колонки `Peru` и `Ecuador` и используя референсы
   `../UI Examples/Peru.png` и `../UI Examples/Equador.png` для формата валюты/цен и моделей
   транспорта на этих рынках.

## Почему остановились и на чём

Figma MCP-сервер (официальный, `mcp__fe213dd3-...__use_figma` и соседние инструменты) на
**Starter-плане ограничен 20 вызовами инструмента в месяц** (плюс 10/мин, но месячный лимит — то,
что реально всё остановило). Источник: https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/
Лимит **сбрасывается вместе с биллинг-циклом аккаунта**, не по таймеру — ждать несколько минут
бессмысленно. Варианты: подождать до сброса или проапгрейдить план Figma для этого файла/команды.

Успели сделать до упора в лимит:
- Полностью разведали структуру страницы Colombia (см. `figma-scripts/00-setup-notes.md` — все node id).
- Выяснили ключевой факт, который сильно упрощает всю дальнейшую работу: на странице **1379
  текстовых нод, но всего 404 уникальных строки** (компоненты и состояния сильно переиспользуются).
  → Не нужно редактировать 1379 нод по одной — достаточно построить словарь из ~400 уникальных строк
  и одним проходом (`figma-scripts/03-write-dictionary-replace.js`) заменить их везде разом.
- Собрали и перевели **245 из ~400 уникальных строк** — уже в `localization-table.csv`, с реальными
  node id для части из них в `raw-data/*.json`.
- Скачали референсные скриншоты текущего состояния (`screenshots/`) и разобрали три референса
  пользователя `../UI Examples/{Colombia,Equador,Peru}.png` — они показывают, что у всех трёх рынков
  **один и тот же UI-копирайт и имена курьеров** (Carlos/Juan/Mateo), различается только
  **валюта/формат цены и модель транспорта** (таблица ниже).
- Пользователь также добавил `../Userpics/{Carlos,Juan,Mateo,Gaurav}.png` — готовые фото курьеров
  для подстановки вместо текущих стоковых.

Не успели (упёрлись в лимит):
- Дособрать оставшиеся ~155 уникальных строк (см. `raw-data/unique-strings-page-wide.json` —
  там указано, какой диапазон уже получен, скрипт для остального — `figma-scripts/01-inventory-unique-strings.js`).
- Полностью получить сырые данные (id+имя+текст) по группам "Search for courier", "Bids", "Order
  statuses" и до конца "Order details" — нужны, если словарной замены недостаточно и придётся
  редактировать что-то по конкретному id (см. `figma-scripts/02-inventory-per-group-with-ids.js`).
- Прогнать сам скрипт записи правок (`03-write-dictionary-replace.js`) — ни одной правки в файл
  ещё не внесено, страница Colombia сейчас в точности как English.
- Заменить фото курьеров и флаг страны (план и заготовка кода — `figma-scripts/04-avatar-and-flag-swap.md`).
- Всё то же самое для Peru и Ecuador.

## Структура папки

- `README.md` — этот файл
- `localization-table.csv` — таблица English → Colombia (ES), 245 строк, готова к расширению
- `figma-scripts/` — готовые к вставке JS-скрипты для `use_figma` + заметки по флагу/аватаркам
- `raw-data/` — все сырые данные, уже вытащенные из Figma (id + текст по группам, дедуплицированный
  список уникальных строк) — чтобы не тратить лимит повторно на то, что уже получено
- `screenshots/` — скриншоты текущего (ещё не переведённого) состояния для сравнения до/после
- Полный план исходной сессии (контекст, все решения по формату) — см. также историю переписки;
  ключевые решения продублированы ниже.

## Ключевые решения (зафиксированы с пользователем)

- Референс-город: **Богота**, адресация вида `Calle 100 # 15-20`.
- Валюта: **`COP 13.500`** (без `$`, код валюты перед суммой, точка — разделитель тысяч) — по
  реальному референсу `../UI Examples/Colombia.png`, а не придумано.
- Служебные подписи на канвасе (заголовки секций, имена фреймов типа "Filled form", "/DTD") —
  **оставляем на английском**, не переводим (см. категорию `SKIP` в CSV).
- Имена курьеров — **только мужские**, короткие, без фамилий (Carlos, Juan, Mateo + одно для 4-й
  аватарки). Имена отправителя/получателя (не курьеры) — любого пола.
- Фото курьеров — из `../Userpics/`, не стоковые.
- **Обращение на "tú", не "usted"** — несмотря на то, что в разговорной Колумбии (особенно Богота
  и Андский регион) бытовое "ustedeo" распространено даже между друзьями, реальные travel/delivery
  приложения на этом рынке (Uber Colombia, Rappi) единообразно используют "tú" во всём копирайте —
  это панрегиональный стандарт индустрии для потребительских приложений в испаноязычной Латинской
  Америке. Вся таблица `localization-table.csv` уже написана на "tú" ("Ingresa tu ruta", "Ofrece tu
  precio" и т.п.) — сохранять этот регистр и для Peru/Ecuador, отдельно решение принимать не нужно.
- Формат для будущих рынков (справочно из референсов, не проверено вживую):

| Рынок | Валюта/формат цены | Пример моделей транспорта |
|---|---|---|
| Colombia | `COP 13.500` (без `$`) | Chevrolet Onix, Bajaj Pulsar 200 |
| Peru | `S/ 16.50` (соли, точка — десятичный разделитель) | Toyota Yaris, Honda GL150 |
| Ecuador | `$4.50` (USD, т.к. в Эквадоре официальная валюта — доллар) | Chevrolet Sail, Shineray XY150 |
