## План действий для Peru/Ecuador (метод дублирования страниц)

1. В Figma (человек, не MCP — **дублирование страницы** программно через Plugin API не всегда
   надёжно сохраняет все связи/инстансы; проще и безопаснее попросить пользователя самого продублировать
   страницу `Colombia` дважды прямо в Figma UI и переименовать в `Peru` и `Ecuador` — как он уже
   делал с дублированием всего файла) **либо** через `use_figma`:
   ```js
   const co = await figma.getNodeByIdAsync('2001:14595');
   const dup = co.clone();
   dup.name = 'Peru'; // или 'Ecuador'
   figma.root.appendChild(dup); // клон страницы — appendChild на figma.root, не на page
   return { newPageId: dup.id };
   ```
   Стоит проверить на маленьком тесте, что `clone()` на PageNode действительно копирует все
   вложенные инстансы/оверрайды 1:1 (в первой сессии это не проверялось).
2. Собрать `DICTIONARY` из CSV для нужного рынка (колонка `Peru (ES)` или `Ecuador (ES)`, без
   `SKIP`), прогнать `03-write-dictionary-replace.js` по новой странице несколькими чанками — **но
   учтите**: раз UI-копирайт (категория `UI`) идентичен Colombia, **при первом проходе среди
   значений много совпадений с уже-испанским текстом** (`next === current`) — это нормально, скрипт
   их пропускает (см. `if (next === current) continue;` в скрипте), реально меняются только строки
   категории `DATA` (адреса/цены/телефоны/номера/модели).
3. **Флаг**: см. секцию "Флаг" ниже — тот же приём (detach + 3 прямоугольника), только с цветами
   нужной страны.
4. **Карточки ставок (Bids)**: используйте точные референсные цифры из таблицы ниже — они не идут
   через общий словарь (см. объяснение в секции Colombia), это **точечные правки по node id** внутри
   новой страницы (id **будут другими** после клонирования! — сначала найдите заново инстансы карточек
   через `frame.query()`, см. `figma-scripts/02-inventory-per-group-with-ids.js`).
5. **Аватарки курьеров**: если сетевой доступ к `mcp.figma.com` из среды выполнения по-прежнему
   заблокирован (см. "Аватарки" ниже) — сначала попросите пользователя вручную подставить фото хотя
   бы на Colombia, повторить для Peru/Ecuador можно будет через `INSTANCE.fills`-копирование
   `imageHash` с уже готовой Colombia-страницы (не нужно заново грузить файлы), см. код в
   "Аватарки" ниже.
6. Проверка: скриншоты ключевых экранов + убедиться, что страница `English` (`0:1`) и уже готовая
   `Colombia` не изменились.

## Флаг

В файле-копии `flags / MX` (компонент страны у поля телефона) — **компонент из библиотеки, которая
отвязалась при дублировании файла в другую команду** (`search_design_system` и `get_libraries`
ничего похожего не находят). Поэтому вместо попытки найти/импортировать компонент `flags / CO` (его
здесь физически нет) — **инстанс детачится и перестраивается вручную из 3 прямоугольников**:

```js
const instance = await figma.getNodeByIdAsync(FLAG_INSTANCE_ID);
const detached = instance.detachInstance(); // ВАЖНО: x/y/resize нельзя менять на инстансе напрямую
                                             // ("cannot be overridden in an instance: relative-transform")
                                             // — только после detachInstance()
for (const c of [...detached.children]) c.remove(); // старые Mask/Vector/Oval-слои мешают, чище удалить
detached.resize(24, 24);
detached.clipsContent = true;
detached.cornerRadius = 3;
detached.fills = [{ type: 'SOLID', color: { r: 1, g: 1, b: 1 } }];
// добавить 3 прямоугольника нужных цветов/пропорций — см. таблицы ниже и полный код в
// figma-scripts/04-avatar-and-flag-swap.md
```

На Colombia было **12 инстансов** флага на странице (все точки с полем телефона) — найти их все
через `page.query('INSTANCE[name*=lag], INSTANCE[name*=Flag]')` на НОВОЙ странице после дублирования
(id будут другими).

Цвета/пропорции (полоса = ширина 24 × высота 8 для верхней трети/половины, дальше делить по факту):

| Страна | Полосы (сверху вниз) | Цвета (RGB 0–1) |
|---|---|---|
| Colombia | жёлтая (½ высоты) / синяя (¼) / красная (¼) | `{1, .807, .086}` / `{0, .235, .635}` / `{.808, .106, .180}` |
| Peru | красная / белая / красная, **вертикальные** полосы равной ширины | красный `{.808, .106, .180}` (тот же, что и Colombia), белый `{1,1,1}` |
| Ecuador | жёлтая (½ высоты, как Colombia) / синяя (¼) / красная (¼), **горизонтальные** — фактически идентична Colombia по структуре, отличается только оттенком (Ecuador жёлтый чуть тусклее в официальном флаге, но для 24×24 иконки разница не критична — можно переиспользовать те же цвета что и Colombia) | те же коды, что Colombia, если не будет иных указаний |

Peru — **вертикальные** полосы (в отличие от Colombia/Ecuador, у которых горизонтальные), так что
код для Peru будет с 3 прямоугольниками `resize(8, 24)` при `x = 0/8/16, y = 0`, а не `resize(24, 8)`
c переменным `y` как в Colombia.

Готовые файлы фото уже лежат в репозитории на ветке `main` (не в этой рабочей ветке!):


(`Gaurav.png` по факту не нужен — 4-й слот не используется, всех троих курьеров хватает: Carlos/Juan/Mateo)

Если сеть всё же доступна — путь такой:

2. `POST` каждого файла как `image/png` на свой `submitUrl` (`curl --data-binary @Carlos.png`).

## Важный технический гэтча этой сессии: невидимые Unicode-символы в исходном тексте

Несколько строк в исходном (английском) макете содержат **невидимые Unicode-символы** вместо
обычного пробела — `U+00A0` (неразрывный пробел) и `U+2028` (line separator). Визуально в Figma и в
выводе инструментов они неотличимы от обычного пробела, но **точное сравнение строк (`===`) их не
матчит** — из-за этого словарная замена молча пропускала эти узлы, а быстрые проверки "не осталось
ли английского" тоже давали ложноотрицательный результат (простой `Set.has(text)` не находил их,
хотя они физически были в файле).

Как диагностировать: искать по code point'ам, не по visual/exact match:
```js
const oddChars = ['00A0','2028','2029','200B','200C','200D','FEFF','202F','2060', /* и другие */];
const oddPattern = new RegExp('[' + oddChars.map(h => '\\u' + h).join('') + ']');
const found = nodes.filter(n => oddPattern.test(n.characters));
```
Как чинить: **нельзя** просто напечатать нужный символ в коде скрипта — Claude/модель не может
надёжно ввести литеральный `U+00A0`/`U+2028` в текст (он "нормализуется" в обычный пробел при
наборе). Нужно собирать ключ словаря программно:
```js
const NBSP = String.fromCharCode(0x00A0);
const LSEP = String.fromCharCode(0x2028);
DICTIONARY.set("Pickup in ~8" + NBSP + "min", "Recogida en ~8 min");
```
На Colombia так нашлось и было исправлено 7 узлов (после первого "исправлено всё" отчёта, который
оказался неполным). **На Peru/Ecuador эти же строки-источники** (если они остались в DATA/UI тексте,
не были перезаписаны) **будут содержать те же скрытые символы** — используйте готовый список из
`figma-scripts/03-write-dictionary-replace.js` (раздел "hidden Unicode fixes"), не выискивайте заново.

Отдельный вывод на будущее: **не доверять единичной автоматической проверке** "остался ли
английский" — она может давать ложноотрицательный результат. Надёжнее: (1) явный
code-point-скан на odd-whitespace, (2) регулярно спрашивать у пользователя визуальную сверку
скриншотами (как в этой сессии — именно так были найдены финальные 4 узла).

## Ключевые решения (зафиксированы с пользователем)

- Референс-город: **Bogotá**, адресация вида `Calle 100 # 15-20`.
- Валюта Colombia: **`COP 13.500`** (без `$`, код валюты перед суммой, точка — разделитель тысяч).
- Служебные подписи на канвасе (заголовки секций, имена фреймов типа "Filled form", "/DTD") —
  **оставляем на английском**, категория `SKIP` в CSV.
- Имена курьеров — **только мужские**, короткие, без фамилий: **Carlos, Juan, Mateo** (закреплено
  окончательно на Colombia, см. "Карточки ставок" выше про фикс María→Mateo). Имена
  отправителя/получателя (не курьеры) — любого пола.
- Фото курьеров — из `Userpics/` (ветка `main` репозитория), не стоковые. **Одни и те же трое** для
  всех рынков (Carlos/Juan/Mateo) — так показывают референсы пользователя по всем 3 странам.
- **Обращение на "tú", не "usted"** — индустриальный стандарт LatAm consumer-приложений (Uber
  Colombia, Rappi), сохраняется на всех рынках без пересмотра.
- Формат по рынкам (референс — скриншоты пользователя, см. таблицу Bids выше за проверенными
  цифрами; общий паттерн):
